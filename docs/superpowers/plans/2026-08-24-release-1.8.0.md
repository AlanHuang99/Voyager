# Voyager 1.8.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the verified resolutions for pull request #54 and issues #53, #55, #56, #57, and #58, close #52 with the approved scope decision, and publish Voyager 1.8.0 with synchronized GitHub and F-Droid metadata.

**Architecture:** Focused implementation commits remain on `codex/github-issues-52-58` and enter `master` through one reviewed feature pull request. A separate release branch bumps version and public metadata after master is green. The release tag triggers the existing signed-APK and Pages workflow; published artifacts are independently checked and installed before F-Droid metadata is pinned to the immutable release commit.

**Tech Stack:** Git, GitHub CLI and Actions, Gradle/Android tooling, ADB Wi-Fi debugging, `apksigner`, `aapt2` or `apkanalyzer`, F-Droid YAML metadata.

**Spec:** `docs/superpowers/specs/2026-08-24-github-issues-52-58-design.md`

## Global Constraints

- Release version is `1.8.0`, version code is `16`, and tag is exactly `v1.8.0`.
- Do not push an implementation branch until its local focused tests pass.
- Do not merge a pull request until GitHub checks pass.
- Do not close an implemented issue until the merged `master` contains its verified change.
- Do not tag until release-branch CI and final local/K60 release verification pass.
- Never expose or commit credentials, tokens, signing secrets, keystores, local auth state, screenshots, logs, or temporary test data.
- Preserve pull request #54 contributor authorship.
- The expected published signing certificate is the repository's pinned SHA-256 `db496277d456751abe8ca6405026337c81a561a134e38d49c8e21fb8f036badf`, but publication fails if fresh `apksigner` output differs.
- Release changelogs describe only behavior that reached `master` and passed verification.
- The user granted explicit current-session permission to push branches, merge pull requests, close issues, create and push `v1.8.0`, and publish the GitHub release.
